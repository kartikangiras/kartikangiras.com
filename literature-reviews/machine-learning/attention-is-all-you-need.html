Attention Is All You Need

Ashish Vaswani, Noam Shazeer, Niki Parmar, Jakob Uszkoreit, Llion Jones, Aidan N. Gomez, Łukasz Kaiser, Illia Polosukhin · NeurIPS 2017

The paper that replaced recurrence with attention, and the architecture behind almost every model I work with. I reimplemented it from scratch in PyTorch to see how the pieces fit.

The problem

Before this paper, the strongest translation models were recurrent or convolutional. RNNs process a sentence one token at a time, so training can't be parallelized across a sequence, and information between distant words has to survive many steps of state. Attention already existed, but only as an add-on to a recurrent encoder and decoder.

The core idea

Drop recurrence entirely and let every token look at every other token directly. Each position produces a query, a key and a value. A token's output is a weighted sum of all the values, with weights from how well its query matches each key. The path between any two words is one step long, and a whole sequence is processed in parallel.

The architecture

  • Scaled dot-product attention. Scores are query-key dot products divided by the square root of the key dimension, then a softmax. Without the scaling, large dot products push the softmax into regions with tiny gradients.
  • Multi-head attention. Instead of one attention over the full width, the model runs 8 smaller heads in parallel (64 dimensions each in the base model) and concatenates them, so different heads can track different relationships.
  • Encoder and decoder stacks. Six layers each. Every sublayer is wrapped in a residual connection and layer norm. The decoder adds masked self-attention, so a position can't see the future, plus cross-attention over the encoder output.
  • Positional encodings. Attention has no notion of order, so position is added to the embeddings with fixed sine and cosine waves. The authors note that learned position embeddings performed almost the same.

Training and results

The models were trained on WMT 2014 translation with Adam, a learning rate that warms up for 4,000 steps and then decays, dropout, and label smoothing. The big model reached 28.4 BLEU on English to German and 41.8 on English to French, beating previous results, including ensembles, at a fraction of the training cost: about 3.5 days on eight P100 GPUs.

What I learned implementing it

My implementation is in kartikangiras/attention-is-all-you-need. It is a single main.py with the full encoder-decoder, written while following Aladdin Persson's tutorial.

  • einsum makes heads readable. Splitting the embedding into a separate head axis and writing the query-key and attention-value products with torch.einsum makes the code read almost line for line like the equations.
  • Masks are where shapes matter. The source gets a padding mask and the target gets a lower-triangular causal mask, and both have to broadcast across the head dimension. Masked scores are set to a large negative number before the softmax so they get no weight.
  • A scaling detail I got wrong. My attention divides scores by the square root of the full embedding size, not the per-head dimension the paper uses. With 8 heads that softens every attention distribution by a factor of about 2.8. It never surfaced because I only checked output shapes, and it's the first thing I'd fix.
  • Learned positions instead of sinusoids. I used a learned position embedding, which the paper found works about as well. The trade-off is that it can't handle sequences longer than the maximum length it was trained with, while sinusoids can in principle.

Limitations

Self-attention costs grow with the square of sequence length, which the paper acknowledges and which later work spent years attacking. Its evaluation is mainly translation, plus English constituency parsing. My own implementation is an architecture study, not a reproduction: it has no training loop, label smoothing, learning rate schedule or beam search, and it is only checked with a random-token forward pass.

Why it matters

Nearly every model in my work, from the agents in Sindarin to the ones DeVries audits, is a descendant of this architecture. Implementing attention also made one safety point concrete for me: inside the model there is no separate channel for instructions and data. Every token in the context can attend to every other, which is a big part of why prompt injection is so hard to rule out at the model level and has to be handled around it.
